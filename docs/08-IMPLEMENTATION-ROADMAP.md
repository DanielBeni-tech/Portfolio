# Implementation Roadmap — Daniel Beni Portfolio

## Phase 0 — Creative direction

Before coding:

- lock identity
- lock typography direction
- lock palette
- collect project screenshots
- define visual references
- create moodboard
- define motion language

Deliverable:

**approved visual direction**

## Phase 1 — Foundation

- initialize Next.js
- TypeScript

## Phase 2 — Hero

Build the strongest section first.

Test:

- desktop
- tablet
- mobile
- reduced motion

Do not continue until the hero feels exceptional.

## Phase 3 — Work

- project data model

- case study template

## Phase 5 — Community

---

## Phase 6 — About + Contact

Make the ending intentionally calmer.

The final page should feel like:

```text
Everything you've seen
        ↓
Now let's build.
```

---

## Phase 7 — Motion polish

Perform a dedicated animation pass.

Do NOT simply add more animations.

Instead:

- remove weak animations
- improve timing
- improve transitions
- fix hierarchy
- add micro-interactions
- test mobile

---

## Phase 8 — Performance

Run:

- Lighthouse
- mobile throttling
- CPU throttling
- image audits
- bundle analysis

Target:

```text
Performance 90+
Accessibility 95+
Best Practices 95+
SEO 95+
```

These are targets, not excuses to compromise design.

---

## Phase 9 — Content polish

Replace placeholder content.

Verify:

- project dates
- roles
- technologies
- links
- metrics
- descriptions

No fabricated claims.

# Final launch criterion

Do not ask:

> "Does the site work?"

Ask:

> **"Does the site itself prove that Daniel knows how to design and build exceptional digital experiences?"**

If the answer is not an immediate yes, keep iterating.
