# Daniel Beni — Portfolio 2026
## Vision & Creative Direction

**Status:** Brainstorm → foundation  
**Owner:** Daniel Beni  
**Direction:** AI Engineer · Software Builder · Community Builder

---

## 1. Core thesis

This portfolio must **not feel like a CV placed inside a website**.

It must feel like a **designed digital product whose existence proves Daniel can design, build, animate and think**.

The old portfolio communicated:

> web designer / freelancer / generic creative developer

The new portfolio should communicate:

> **I build intelligent software, real products and technical communities — and I care deeply about how those things feel.**

The website itself is the first case study.

### Creative rule

**Don't tell visitors that Daniel is a good designer/developer. Make the interface demonstrate it.**

### "The portfolio is a living system."

## 6. Design references

### Moritz Dunkel

The reference site demonstrates an important principle: strong design is not decoration. The website repeatedly connects visual quality with positioning, trust, portfolio evidence, process and outcomes.

Useful lessons to borrow:

- extremely clear positioning
- confident typography
- strong hierarchy
- visual proof instead of empty claims
- project presentation as evidence
- strategic storytelling
- clear CTAs
- repeated visual language
- personality without sacrificing clarity

Do **not** copy the visual identity.

Reference: https://www.moritzdunkel.de/

### Other creative principles

We can also learn from modern creative-development portfolios that use:

- editorial layouts
- scroll choreography
- GSAP / Framer Motion style motion systems
- WebGL where it adds meaning
- project transitions
- large typography
- cursor interactions
- masked image reveals
- magnetic interactions
- kinetic typography
- horizontal movement
- immersive case studies

A portfolio case-study article from Codrops shows how animation can connect a dark homepage to brighter project pages through a coherent transition system rather than using random effects.

## 7. Anti-generic rules

### Absolutely avoid

- generic purple AI gradients
- stock photos of programmers
- random floating 3D cubes
- excessive glassmorphism
- every element bouncing
- fake statistics
- fake testimonials
- fake clients
- generic "passionate developer" copy
- skill bars like "React 95%"
- template-looking project cards
- huge walls of text
- animation without narrative purpose

### Instead

Use:

- typography
- rhythm
- negative space
- contrast
- editorial composition
- real screenshots
- real project data
- real GitHub activity
- subtle technical diagrams
- purposeful motion
- visual storytelling

## 10. Signature visual language

Introduce recurring motifs:

### A. Coordinate labels

Example:

`YAOUNDÉ / CAMEROON`

`03 — SELECTED WORK`

`AI / SOFTWARE / COMMUNITY`

### B. Technical annotations

Small notes such as:

`BUILD STATUS: EXPERIMENTAL`

`SYSTEM: LOCAL AI`

`STACK: PYTHON / FASTAPI / POSTGRES`

### C. Lines

Thin rules can structure the page and create a technical/editorial feeling.

### D. Numbers

Section numbering:

`01 / 06`

`02 / 06`

Numbers should be large enough to become visual elements.

### E. Cursor / pointer

A custom cursor can become part of the brand on desktop, while touch devices receive equivalent hover-independent interactions.

## 14. Core principle

### Motion is not decoration.

Every animation must answer one of these questions:

- Does it establish hierarchy?
- Does it explain a relationship?
- Does it reveal information?
- Does it create continuity?
- Does it reward exploration?
- Does it communicate technical ability?

If the answer is no, remove the animation.
